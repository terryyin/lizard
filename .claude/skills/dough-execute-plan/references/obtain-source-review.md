# Obtain the source-only review

To obtain a source-only review, spawn a fresh general-purpose reviewer without
conversation inheritance, fork or resume; do not reuse the implementation or
refactor agent. Supply only the original source text and explicit human
amendments: the selected story's Goal, Scope, key examples and exclusions,
complete correction input, or authorized quick instruction. Give no plan,
return, product, proof, suspected omission or current-slice scope. For a
plan-homed correction, send its original correction input, not its slicing.
Tell the reviewer: use only these inputs, read no other project files, change
nothing; return source clauses with individual commitments, qualifications,
trigger/journey examples and exclusions. Number every commitment, and give each
item of a listed compound commitment its own id (for example `4a.1`–`4a.6` for
six listed filters). Separate compound promises; preserve alternatives without
turning examples into rejection rules. Derive promises, not slice ownership or
acceptance. Use supported fresh-context delegation or a separate new session
with these limits. Retain the actual reviewer launch/input and returned
commitments, or their inspectable locations, in existing acceptance evidence; a
coordinator's assertion is insufficient.

## Retain, link, and allocate

When you retain the return beside the plan as `source-review.md`, use its
[record form](story-obligations.md#record-the-source-review), link it from the
plan by `**Source review:**`, and allocate every id: to the slice whose output
owes it, to a disposing obligation, or, if only a post-execution operation can
observe it, to its
[lifecycle owner](story-obligations.md#record-the-source-review).

## Before planned delegation

For planned execution, obtain that review before the first implementation
delegation—whatever that first slice's type—and again before the next
delegation after a human story amendment. Retain, link, and
[allocate](#retain-link-and-allocate) every id before the obligations listing
at that delegation. Reuse a plan that already links a retained review for the
unchanged source; allocate any still-unallocated row before that listing. After
a story amendment, obtain a fresh review, replace it and allocate it again the
same way. If isolation or that evidence is unavailable, name the missing review
and stop this delegation.

## At acceptance

Before comparing a slice's return, have a source-only review of its unchanged
source. For planned execution, reuse the retained review while the source text
is unchanged; do not launch another reviewer. When none is retained, obtain one
under the rules above, then retain, link, and
[allocate](#retain-link-and-allocate) every id before the next obligations
listing or check. If isolation or that evidence is unavailable, name the
missing review and stop dependent acceptance.

For planned execution, record the acceptance comparison per returned id in
`source-review.md`, allocating and observing each id under its
[record rules](story-obligations.md#record-the-source-review).
